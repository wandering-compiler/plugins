### Added

- **`membership_kinds`: one identity, several memberships of several kinds** — the auth half of audience surfaces (a domain publishing one REST / MCP / gRPC surface per audience, each on its own gateway). `OrgMembership`, `OrgInvite` and `UserRole` gain a kind (`staff`, `client`, …), and the membership and pending-invite unique indexes move onto it, so a person may be an organization's staff and its client at once. An audience gateway names the kinds it admits in every `Authenticate` (`x-w17-membership-kinds`, gateway-owned): the organization a request acts in is resolved among the memberships of an admitted kind, a caller holding none is refused 403 `MEMBERSHIP_NOT_ADMITTED` before any handler, only the roles that came with an admitted membership count (`AuthQuery.ListUserRoleKinds`), and ownership does not widen. `InviteToOrg` takes the kind of membership accepting creates (with `org_invite`). A gateway that names no kinds admits every membership, so nothing changes without audiences. Off by default; requires `org_membership`; a migration adds the columns.
