### A request that names no organization says what it set aside

A request that could have named an organization (the `W17-Org` selector is accepted there) and named none — a member of several, or of one where `org_from_sole_membership` is off — still holds only the realm-wide roles. `Authenticate` now also answers, as the scope `org_permissions`, the permission ids of the roles it set aside (the roles held inside organizations; `*` for a wildcard one), and to a product's gateway the product's permission codes held there, as `org_product_roles` (the identity's own ids are dropped from a product's answer). The gateway reads them when a permission is missing and answers `FAILED_PRECONDITION` / `ORGANIZATION_REQUIRED` — "name the organization (W17-Org)" — instead of `PERMISSION_DENIED` / `MISSING_PERMISSION`, which read the same as having no access at all. Nothing is ever selected for the caller, and nothing about any organization is said: only what the caller holds. A gateway built from an SDK before the change ignores the scopes. An organization's packages or plan are not applied to the hint, so a request that names an organization may still be refused as `MISSING_PERMISSION`; a permission held only through a team's roles is not in it. Unchanged: an organization the caller is not a member of answers `UNAUTHENTICATED` / `ORG_NOT_MEMBER`.
