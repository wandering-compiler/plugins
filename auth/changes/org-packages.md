### Added

- **`org_packages`: what an organization can hold is bounded by its packages.** A project names packages — sets of its methods and audiences — in the domain's protos (`(w17.packages)`, w17/packages.proto); the backoffice gives and takes them per organization, realm-wide (`AddOrgPackage` / `RemoveOrgPackage` / `ListPackagesOfOrg`), and an organization reads its own (`ListMyOrgPackages`). On every `Authenticate` in an organization a project method's permission survives only when one of its packages grants it — the owner's wildcard included — so a method no package grants is held by nobody (default deny), and the role ceiling keeps anyone from handing out a role above the packages. An audience gateway admits a member only when a package opens its audience (`PACKAGE_AUDIENCE_OFF`). Plugin methods and realm-wide requests are not narrowed; taking a package applies on the next request; nothing is deleted. The table, `w17_packages`, is generated by codegen. Off by default; requires `org_membership`; a migration adds the table.
