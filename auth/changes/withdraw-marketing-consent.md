### A withdrawal made in the marketing tool reaches the user's consent

`AuthService.WithdrawMarketingConsent` (`marketing_consent`) records that the user withdrew their marketing consent outside the project — they unsubscribed in the marketing tool — through the same statement and event as their own `SetMarketingConsent`: `User.marketing_consent` becomes false with its time, and `MarketingConsentChanged` announces it. It can only withdraw (a consent is the user's to give). It takes `withdrawn_at`, when the user withdrew it there: a withdrawal already on record, and any decision the user made after `withdrawn_at`, is answered as it stands, so a late or redelivered unsubscribe never cancels a newer consent. It names the user, so it is marked `(w17.contrib.plugin_internal_rpc)`: codegen refuses it on every surface, and only the domain's own code calls it — the business method a project binds to the marketing plugin's `consent_withdrawn` hook.
